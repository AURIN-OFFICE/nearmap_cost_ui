## 2. Failed-tile undercount (caveat A)

`adelaide_sample_pavement_condition` requested an invalid resource (`aiPacks:pavement_condition`), so all 42 tiles errored and were skipped. The plan total reads **0 credits** — a silently-low number. The UI surfaces `tiles_failed` so this can't be mistaken for an authoritative estimate.

## 3. Synthetic multi-pack divergence (caveat C)

Offline data is single-pack, so the cap-at-7 bug isn't visible above. Using adelaide_sample (~12.16 km², per-pack API cost = 60,900 credits) and projecting per-pack billing (validated T2/T4: each pack is a separate charge):

`by_area` stops growing after 7 packs (the refuted bundle assumption), so it increasingly **under-estimates** as more packs are selected — the key reason `by_api_return` is the more correct figure.
